# Architecture Reference

anthrouter's request handling is built on a few linked concerns: routing requests to cheaper models, stripping volatile prompts, persisting decisions, and exposing admin APIs.

## Request path (`anthrouter/handlers.py`)

One inbound `/v1/messages` request walks, in order: local-command interception → model-tier routing → system-prompt sanitization → upstream dispatch (`AnthropicTransport`) → single-pass SSE/JSON usage-and-text extraction → DB record → response, with the client's originally-requested model name echoed back regardless of what was actually routed to.

There is no handler-level retry. `AnthropicTransport` already retries 429s (honoring upstream retry timing) and 5xx in-connection; with one backend there's nowhere else for a failed request to go. This means the routing decision and the prompt-hash pair are derived exactly once per request — no stash/restore across attempts.

`ProxyRequestHandler` is a `BaseHTTPRequestHandler` reused across keep-alive requests, so `_reset_request_state()` clears all per-request instance attributes at the top of `do_GET`/`do_POST`. Collaborators (`config`, `transport`, `sessions`, `request_db`, `oauth_cache`) are class attributes injected once by `server.make_handler_class()` — never touch `self.__class__` state per-request.

## Model-tier routing (`anthrouter/model_router.py`, `model_tier.py`, `session_state.py`)

Central decision function is `route_model()`. Order of precedence, each outranking the next:

1. **Long-context size floor** — a deterministic, pre-classifier check. If `estimate_input_tokens()` (calibrated by a per-session actual/estimate ratio) or the last measured session context crosses `--auto-model-routing-long-context-threshold`, force the `--auto-model-routing-long` target (e.g. `opus[1m]`) and inject the `context-1m` beta. Applies even to text-less continuation turns.
2. **Walk-back cache** — a text-less turn (tool-result-only, or no usable final-user text) replays the session's last classified tier from `SessionState` rather than reclassifying recovered boilerplate. Capped so a replay can never *upgrade* past what the client actually requested (`_cap_cached_tier`); tool-result-only continuations bypass that cap since the client resends the base model unconditionally on every agentic turn.
3. **Affirmation inheritance** — a bare "yes"/"proceed" turn inherits the conversation's established tier instead of being freshly (mis)classified as trivial.
4. **Classifier** — two modes selected by `--auto-model-routing-mode`: `classifier` (default, calls a lightweight LLM — the configured `--auto-model-routing-classifier-model` — with a bounded JSON summary and gets back a 0–100 complexity score, thresholded into trivial/standard/deep), `rules` (deterministic keyword matching, no LLM call).

**Final user turn (ADR-0011).** `build_routing_summary()` takes the last `role:'user'` entry within the trailing `_TRAILING_SCAN_LIMIT` (8) messages as the final user turn: the `role:'system'` tool-loop terminators Claude Code 5.x appends are skipped, and the skip count is exposed as `RoutingSummary.trailing_skipped` (routing-internal, never in `to_classifier_json()`). No user entry within the limit yields `missing_final_user_text`. From that turn, text recovery prefers its own text, then transcript recovery, then bounded walk-back over earlier messages.

**Classifier-input privacy:** See the root `CLAUDE.md` § Classifier-input privacy for the enforcement contract — that is the authoritative copy.

The sentinel mechanics behind that contract: classifier payloads carry `_anthproxy_internal_classifier: True`. `route_model()` no-ops immediately on any payload already carrying it, preventing recursive classification. `build_body` strips the key before dispatch, so a chained anthrouter or anthproxy hop never receives it. The guard therefore protects only payloads that reach `route_model` in-process, or payloads a client sends with the key set.

**Classifier budget and Haiku 5.5 effort gate (spec #24, ticket #25).** `_CLASSIFIER_MAX_TOKENS` and `_CLASSIFIER_MAX_TOKENS_JSON` are both 256. The main, system-prompt and affirmation classifiers share these constants. The value is a ceiling: Haiku 5.5 thinks by default, thinking tokens count against `max_tokens`, and unused budget costs nothing. The budget applies to every classifier model. `build_body` sets `output_config.effort` to `low` on a classifier payload only when two conditions hold: the inbound payload carries a truthy `_anthproxy_internal_classifier` and the resolved model ID contains `haiku-5-5`. The gate runs after the top-level effort strip and before the per-message effort gate and the thinking gates. It reads the sentinel from the inbound `payload` because `_INTERNAL_KEYS` is removed from `body` first. Override: a non-dict `output_config` becomes a new dict, and `effort` is always set to `low`, replacing any value already present (anthproxy parity); other `output_config` keys are kept. Normal client requests never carry the sentinel, so client effort on Haiku 5.5 is unchanged; a client that sends the sentinel by hand gets the gate too (not a security boundary). Other classifier models (Haiku 4.x, Sonnet, Opus, Fable) get no effort change.

**Classifier failure evidence (spec #24, ticket #27).** `classifier_invalid` and `classifier_failed` are fail-closed decisions that still record the classifier call. They carry `classifier_model`, `classifier_summary_json` and `classifier_format`, and a raw slot in `classifier_raw_response`. On `classifier_invalid` the slot holds a text preview of the response: `<no-content>` when `content` is absent or not a list, `<non-text>` when the list has no text block, the usage tokens are booked, and `classifier_stop_reason` holds the response `stop_reason`. On `classifier_failed` the slot holds an exception preview: `HTTP <status_code> <ExceptionClass>: <message>` when the exception has a truthy `status_code` and is not a transport failure (`connection_error`), otherwise `<ExceptionClass>: <message>`, or the class name alone when the message is empty. A transport failure such as an exhausted-retry socket error therefore gets no `HTTP` prefix even though its status is synthetic (502). Carriage returns and newlines in the message become spaces. Tokens are 0 and the stop reason is None. Previews are capped at 120 characters plus `…`, so only the message tail is cut. `classifier_overhead_usd` is computed whenever a classifier call ran: 0.0 for a priced classifier model with zero tokens, NULL for an unpriced one. The `classifier_invalid` warning logs the stop reason, content block types and usage object. Success, rules, walk-back, affirmation and size-floor decisions keep `classifier_stop_reason` None. Affirmation-path invalid outcomes are not covered by this section.

`SessionState` (in-memory, bounded to 1000 entries per map, LRU-evicted, nothing survives a restart) stores two *different* key shapes side by side: the routing on/off override is keyed by the bare session key (`metadata.user_id`), while the routed-tier cache and context observations are keyed by the *context key* — session key + hash of the first user message — so a Claude Code Task sub-agent sharing its parent's `user_id` doesn't clobber the parent's cached tier.

## Sanitizer (`anthrouter/sanitizer.py`, `prompt_volatility.py`)

`sanitize_system_prompt()` runs once per attempt, after hashing the client's system prompt and before dispatch. In `strip` mode it removes allowlisted volatile blocks (e.g. a per-request billing header that invalidates the cached prefix every turn); `warn` only logs; `off` is inert. The pre-strip hash is always what gets recorded as "the prompt as the client sent it" — the sanitized hash is separate and NULL means "sanitizer didn't run," not "found nothing." An unrecognized volatile block is flagged but never silently dropped.

## Transport (`anthrouter/transport.py`, `http_util.py`, `mapper/`)

`AnthropicTransport` holds no credentials — `extract_client_credentials()` rejects (401) any request missing both `x-api-key` and `Authorization`, never substitutes anthrouter's own. `mapper/anthropic_transform.py` does model-aware request shaping (alias resolution via `model_config.py`, beta merging) — needed *only* because routing can rewrite the model to a tier that rejects a field the original tier accepted (e.g. Haiku 4.x rejects top-level `output_config.effort` with HTTP 400; fable rejects per-message `output_config.effort` without the `mid-conversation-output-config` beta). Every such gate fails open (except Haiku effort and adaptive thinking, which strip any non-5.5 Haiku ID): an unrecognized model family keeps the field and lets the 400 surface naturally rather than guessing. `build_body` also adds a field, not only strips one: the classifier effort gate sets `output_config.effort` to `low` on Haiku 5.5 classifier payloads (see **Classifier budget and Haiku 5.5 effort gate** above).

A thinking-block 400 (opus-generated signature invalid for a downgraded sonnet/haiku tier mid-session) triggers exactly one retry with all thinking/redacted_thinking blocks stripped from history.

**Inline `role:'system'` messages (ADR-0010).** Claude Code 5.x appends `role:'system'` entries to `messages[]`; Sonnet 5.5 and Opus 5.5 accept them, Sonnet 4.6 and Haiku answer HTTP 400. `build_body` runs `_rewrite_inline_system` last — it is the only gate that touches `messages[]` — when the resolved model matches `_SYSTEM_ROLE_REJECTING_FAMILIES` (substring match) or the caller passes `force_rewrite=True`. Each system message becomes one `<system-reminder>…</system-reminder>` text block carrying that message's `cache_control`, appended to the `role:'user'` message directly before it; a leading system message, or one after an assistant turn without `tool_use`, becomes a standalone user message; one after an assistant `tool_use` turn is dropped with a WARN (a user turn there would split the tool call from its result). Message-level `output_config` on the system entry is discarded. The content is never folded into top-level `system` — that grows `system[]` one block per turn and defeats the prompt cache. Models outside the tuple keep their inline system messages, `cache_control` included (fail open).

The recovery for that fail-open path sits in `_send_with_retries` beside the thinking-block retry: a 400 whose body mentions both `system` and `role`, on an attempt that did not rewrite, for a payload holding at least one `role:'system'` entry, triggers exactly one rebuild with `force_rewrite=True` and a WARN naming the resolved model so the family can be added to the tuple. A second 400 propagates unchanged. The retry runs before HTTP 200 is committed, so it covers both streaming and non-streaming requests.

## Persistence (`anthrouter/db.py`, `admin.py`)

SQLite, one write connection guarded by a lock, per-thread read connections over WAL. Three tables: `requests` (one row per dispatch, routing decision folded in), `prompt_store` (deduped/ref-counted system+tools content), `sanitizer_events`. FTS5 external-content trigram index over prompt/response text for substring search without a casefolded shadow column.

`admin.py` has two entry points:
- `handle_get` — read-only queries, always enabled
- `handle_post_config` — live config edits, enabled only when `ANTHROUTER_ADMIN_TOKEN` is set (see ADR-0005)

## Local commands

`proxy-help`, `proxy-status`, `proxy-set-model-routing:on|off[:session]` are intercepted in `handlers.parse_local_command()` *before* any credential parsing or upstream dispatch — they never leave the proxy. Matching happens on the exact final user message text after Claude-Code wrapper-tag stripping.
