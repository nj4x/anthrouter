# Answer Claude Code activity-label prompts locally with a filler verb

Claude Code asks for a 3-5 word activity label for each live sub-agent. The final user turn of that request starts with `Describe your most recent action in 3-5 words`. anthrouter treats it as an ordinary request: it runs the classifier, routes the request, and dispatches it upstream. In anthproxy, where these requests are recorded, 6537 of them cost $447.66 between 2026-10-03 and 2026-10-11, about $56 a day (anthproxy ADR-0041, Context). anthrouter serves the same Claude Code traffic.

anthproxy ADR-0041 answers these prompts locally from a stored conversation summary, generated by a summary daemon, and falls back to a random verb when no summary is ready. anthrouter has no summary daemon and no summary tables, so it has nothing better than the fallback verb to reply with.

## Decision

1. **Detect.** The request is an activity-label request when the final user turn, located as routing locates it (the last `role:'user'` entry within the trailing `_TRAILING_SCAN_LIMIT` messages, ADR-0011), starts with `ACTIVITY_LABEL_PREFIX` after `strip_reminders`. The match is case-sensitive. A payload that carries the classifier sentinel `_anthproxy_internal_classifier` is never intercepted.
2. **Answer locally, before routing.** `_handle_messages` checks right after the security-monitor intercept, before credential extraction, routing, and dispatch. No classifier call, routing-state write, tier-cache write or upstream call happens. The reply is a verb picked at random per ask from `ACTIVITY_LABEL_FALLBACKS` (the same ten verbs as anthproxy), so the label changes on every ask. It is sent as SSE or JSON according to the client's `stream` flag and echoes the requested model, like the other local replies.
3. **Record nothing.** The request writes no DB row, as `_handle_happy_new_year` does. anthrouter's `requests` table has no `backend` column to mark a local reply, so a zero-cost row would mix into the routing summary and stats as an ordinary request. One INFO line, `operation=activity_label_local`, is logged.
4. **Flag.** `--activity-label-local-reply` / `ANTHROUTER_ACTIVITY_LABEL_LOCAL_REPLY`, default on. `--no-activity-label-local-reply` sends the prompts upstream as before. The flag is CLI/env only and not editable from the admin UI.

## Considered options

- **Port the summary daemon too.** This gives labels that describe the work. It needs `summary.py`, the summary tables, the conversation anchor column and the daemon wiring, a subsystem anthrouter left out on purpose. Rejected for this change.
- **Record a zero-cost row with a new reason code.** This makes the savings visible in the admin UI. It needs a new `ReasonCode` and changes to `get_routing_summary` and the stats queries to exclude or bucket the rows. Rejected for now. It can be added later without changing the reply.

## Consequences

- An activity-label request costs no classifier call and no upstream call.
- Every sub-agent label in Claude Code is a filler verb ("Cooking", "Pondering", ...), not a description of the work. This is a cosmetic loss.
- Intercepted requests do not appear in the DB, the admin UI or the routing summary. The INFO log line is the only trace.
- A Claude Code change to the prompt wording turns the intercept off silently: the requests go upstream again, as before this ADR.
